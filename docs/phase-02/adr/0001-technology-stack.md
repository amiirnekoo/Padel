# ADR-001: انتخاب استک فناوری هسته پلتفرم پدل (Technology Stack)

**وضعیت:** پذیرفته‌شده (Accepted)
**تاریخ:** 2026-09-21
**تصمیم‌گیرندگان:** تیم مهندسی و مالک محصول

## زمینه و مسئله (Context)

در فاز اول پروژه پدل، خط مبنای کاندید فناوری شامل `FastAPI + Python` برای لایه بک‌اند، `React + TypeScript` برای لایه رابط کاربری، و `PostgreSQL` برای پایگاه داده تراکنشی معرفی گردید. با ورود به فاز دوم، الزامات حاکمیت مهندسی ایجاب می‌کند که این انتخاب به صورت رسمی و با ارزیابی جایگزین‌ها، نیازمندی‌های غیرعملکردی (زمان پاسخ p95 < 300ms و لود < 1s)، اکوسیستم تست و سهولت انطباق با قواعد پیچیده دامنه اعتبارسنجی و تثبیت شود.

گزینه‌های مورد بررسی:
1. **بک‌اند:**
   - گزینه الف: `FastAPI + Python 3.12` (انتخاب منتخب)
   - گزینه ب: `Node.js + Express / NestJS + TypeScript`
   - گزینه ج: `Go + Gin / Fiber`
2. **فرانت‌اند:**
   - گزینه الف: `React 18 + TypeScript + Vite` (انتخاب منتخب)
   - گزینه ب: `Next.js 14 (App Router)`
   - گزینه ج: `Vue 3 + Vite`
3. **پایگاه داده:**
   - گزینه الف: `PostgreSQL 16` (انتخاب منتخب)
   - گزینه ب: `MySQL 8.0`
   - گزینه ج: `MongoDB`

## تصمیم (Decision)

استک فناوری هسته پلتفرم پدل به شرح زیر تصویب شد:

1. **لایه بک‌اند:**
   - **زبان و فریم‌ورک:** `Python 3.12` همراه با `FastAPI`.
   - **ORM و دسترسی به داده:** `SQLAlchemy 2.0` (در حالت Async) همراه با درایور `asyncpg`.
   - **مدیریت شمای داده و اعتبارسنجی:** `Pydantic v2` جهت DTOها و سریال‌سازی با کارایی بالا.
   - **مایگریشن پایگاه داده:** `Alembic`.
   - **چارچوب تست:** `pytest` و `pytest-asyncio`.

2. **لایه فرانت‌اند:**
   - **کتابخانه و ابزار ساخت:** `React 18` همراه با `TypeScript` و `Vite`.
   - **مدیریت استایل و چیدمان:** CSS ماژولار و توکن‌های طراحی Vanilla CSS با پشتیبانی بومی از راست‌به‌چپ (RTL) و فونت استاندارد وزیرمتن (Vazirmatn).
   - **مدیریت وضعیت و کلاینت داده:** React Query (TanStack Query) و کلاینت اختصاصی Axios.
   - **چارچوب تست:** `Vitest` و `Testing Library`.

3. **لایه داده تراکنشی:**
   - **پایگاه داده:** `PostgreSQL 16`.
   - **دلایل انتخاب:** پشتیبانی کامل از تراکنش‌های ACID، مکانیزم‌های قفل‌گذاری سطری پیشرفته (`FOR UPDATE`)، قابلیت پشتیبان‌گیری پیوسته تراکنش‌ها (Continuous WAL Archiving / PITR) جهت تضمین RPO < 1h، و پشتیبانی غنی از فیلدهای JSONB و ایندکس‌های BRIN/B-Tree.

## پیامدها (Consequences)

### پیامدهای مثبت:
- توسعه فوق‌العاده سریع منطق پیچیده ماشین‌های وضعیت ۶گانه بر بستر پایتون و Pydantic.
- کدنویسی تمیز با ساختار Async IO در FastAPI برای پاسخگویی به درخواست‌های هم‌روند در کمتر از ۱۰۰ میلی‌ثانیه.
- تایپینگ قوی دوطرفه در فرانت‌اند با TypeScript که مانع خطاهای Run-time می‌شود.
- پایداری کامل داده‌های مالی و رزرو در PostgreSQL بدون نگرانی از تداخل داده.

### بدهی فنی یا محدودیت‌ها:
- در مقایسه با Go، مصرف حافظه پایتون اندکی بالاتر است که با توجه به مقیاس پایلوت (۳ تا ۵ باشگاه و ۵۰ رزرو هفتگی) کاملاً بهینه و پذیرفتنی است.
- لزوم مدیریت دقیق نشست‌های دیتابیس در حالت ناهمگام (Async Session Management).
