# ADR-003: ساختار مخزن و پوشه‌بندی یکپارچه (Monorepo Structure)

**وضعیت:** پذیرفته‌شده (Accepted)
**تاریخ:** 2026-09-21
**تصمیم‌گیرندگان:** تیم مهندسی و مالک محصول

## زمینه و مسئله (Context)

پروژه پلتفرم پدل شامل اسناد تصمیم‌گیری محصول، قواعد عملیاتی، هسته سرویس‌های بک‌اند، رابط کاربری متصدی و بازیکنان، اسکریپت‌های مایگریشن و خطوط لوله CI/CD است. تفکیک مخزن به دو بخش مستقل (Polyrepo) ممکن است هماهنگی بین DTOها، تغییرات اسناد فازها و قراردادهای API را با تاخیر یا ناهماهنگی نسخه‌ای مواجه کند.

## تصمیم (Decision)

تصویب شد که ساختار پروژه به صورت یک **Monorepo تمیز، سبک و استاندارد** در یک مخزن گیت واحد ساماندهی گردد:

```
Padel/
├── .agents/                      # قوانین، مهارت‌ها و پروتکل‌های هوش مصنوعی و چک‌پوینت
│   ├── rules/
│   └── skills/
├── backend/                      # هسته نرم‌افزاری بک‌اند (FastAPI)
│   ├── app/
│   │   ├── api/                  # اندپوینت‌های REST (نسخه v1)
│   │   │   └── v1/
│   │   │       ├── auth.py
│   │   │       ├── clubs.py
│   │   │       ├── slots.py
│   │   │       ├── bookings.py
│   │   │       └── payments.py
│   │   ├── core/                 # تنظیمات پیکربندی، پایگاه داده و امنیت
│   │   │   ├── config.py
│   │   │   ├── database.py
│   │   │   └── security.py
│   │   ├── models/               # مدل‌های دیتابیس SQLAlchemy 2.0
│   │   ├── schemas/              # اسکیمای اعتبارسنجی Pydantic v2
│   │   └── services/             # موتور ماشین‌های وضعیت و قواعد دامنه
│   ├── alembic/                  # اسکریپت‌های مهاجرت پایگاه داده
│   ├── tests/                    # تست‌های واحد، هم‌روندی و یکپارچگی
│   │   ├── unit/
│   │   └── concurrency/
│   ├── pyproject.toml
│   └── Dockerfile
├── frontend/                     # رابط کاربری وب (React + TypeScript + Vite)
│   ├── src/
│   │   ├── assets/
│   │   ├── components/           # کامپوننت‌های اشتراکی UI
│   │   ├── hooks/                # هوک‌های سفارشی React
│   │   ├── pages/                # صفحات تقویم، باجه متصدی و رزرو
│   │   ├── services/             # کلاینت ارتباط با API
│   │   ├── styles/               # توکن‌های طراحی، رنگ‌ها و استایل‌های RTL
│   │   ├── App.tsx
│   │   └── main.tsx
│   ├── package.json
│   ├── tsconfig.json
│   └── vite.config.ts
├── docs/                         # اسناد معتبر و مصوب محصول و معماری
│   ├── phase-01/                 # منشور، شواهد، قواعد و قرارداد فاز اول
│   └── phase-02/                 # اسناد تصمیم‌گیری معماری (ADR)
└── .github/
    └── workflows/                # پایپ‌لاین‌های اعتبارسنجی و تست خودکار
```

## پیامدها (Consequences)

### پیامدهای مثبت:
- یکپارچگی اتمیک در Commitها و ثبت Checkpointها با مهارت `padel-github-checkpoint`.
- دسترسی سریع به اسناد مرجع در کنار کدهای پیاده‌سازی.
- سهولت در اجرای تست‌های End-to-End و اسکریپت‌های اعتبارسنجی اسناد در ریشه پروژه.

### محدودیت‌ها:
- حجم مخزن کمی بیشتر می‌شود که با استفاده از فایل `.gitignore` مناسب برای پوشه‌های `node_modules` و `.venv` به طور کامل کنترل می‌گردد.
