# قانون دائمی ثبت Checkpointهای مهم در GitHub

این قانون در تمامی نوبت‌ها و پس از اتمام هر مجموعه تغییر معنادار در پروژه پدل اعمال می‌شود:

1. **ارزیابی اقدام مهم:** در پایان هر تسک، بررسی کن آیا یک «اقدام مهم» (شامل تصویب تصمیم محصولی، تکمیل یا اصلاح سند مرجع، اتمام یک گیت، تغییر معماری، رفع خطا، یا تغییر قواعد دامنه) انجام شده است یا خیر.
2. **اجرای خودکار Skill:** در صورت تحقق اقدام مهم، مهارت `padel-github-checkpoint` را فوراً اجرا کن.
3. **پرهیز از Commitهای بی‌مورد:** اگر اقدام مهمی صورت نگرفته (تنها مکالمه، جست‌وجو یا تغییر موقت بوده)، هیچ Commit یا عملیات Push انجام نده.
4. **زمان‌بندی ارزیابی:** این بررسی فقط یک‌بار در پایان هر تسک یا مجموعه تغییر منسجم صورت می‌گیرد، نه بعد از هر فرمان خرد.
5. **عدم گسترش دامنه:** ثبت در GitHub نباید موجب ورود به پیاده‌سازی زودهنگام کد یا خروج از دامنه تسک جاری شود.
6. **تفکیک فایل‌ها:** فایل‌های متفرقه یا تغییرات نامرتبط کاربر هرگز نباید وارد Stage و Commit شوند.
